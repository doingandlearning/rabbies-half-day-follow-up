# Module 2 — Mob-Write a Real Spec, End to End

**Core session — AI-Assisted Development for Laravel Teams: Half-Day Follow-Up**

## Overview

The bulk of the half day. The whole team works together on one real, upcoming story pulled from their own backlog — not a synthetic exercise. As a group, they mob-write a spec for it, drafting a first-cut team spec template as they go so the format is theirs rather than borrowed wholesale from `create-prd`. The spec is then run through to generated output and checked against the story's actual acceptance criteria, and the team explicitly agrees where human sign-off stays non-negotiable.

This session only works with real preparation: a genuine story, agreed and reasonably scoped, before the day.

## Learning objectives

By the end of this session, participants will be able to:

- Run a planning conversation that surfaces requirements, edge cases, and non-goals before any code is written
- Use their own first-cut spec template — adapted from `create-prd`, not copied — to capture a real story
- Take a spec through to generated output and check it against acceptance criteria, not just "does it look plausible"
- State explicitly which decisions require human sign-off regardless of how good the tooling gets, as an agreed team position rather than an unstated assumption

## Suggested running time

90 minutes

## Session structure

| Section | Time |
|---|---|
| Pick the story, set the scene | 5 min |
| Mob-write the spec — planning conversation | 25 min |
| Tighten the spec, draft the team template as you go | 20 min |
| Generate output from the spec | 15 min |
| Check output against acceptance criteria | 15 min |
| Agree explicit sign-off points | 10 min |

## Preparation required

**Before the session**: agree a real, upcoming story with the team lead or whoever owns the backlog. It needs to be small enough to spec and generate a first pass within 90 minutes — a single feature or a well-bounded slice of one, not an epic. Confirm it in advance; do not pick it live, or the session loses most of its working time to scoping.
